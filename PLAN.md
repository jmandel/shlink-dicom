# Detailed API Design, Data Structures & Test Plan: `shlink-dicom`

## 1. Core Architectural Contracts

1. **Zero-Knowledge Server Contract:**
   - The server stores and serves only ciphertext (`bundle.jwe` and `{fileId}.bin`).
   - The 32-byte SHL `key` is generated by the client (browser WASM or CLI) and **never sent to the server**.
   - When share settings change via `PATCH /api/shares/{shareId}` (e.g., adding a passcode, which switches `mode` from `"U"` to `"manifest"` and `shlFlag` from `"U"` to `"P"`), the old URL ceases to resolve (`404`) and the client recalculates a **new `shlink:/...` URI** locally using its stored `key`. The UI states clearly that changing between `U` and `P` mode mints a new link that must be re-shared (and that anyone who already downloaded ciphertext under the same `key` still has it).
2. **Public Demo Protection & Quotas:**
   - Pre-seeded demo shares (`mri-brain-2020.tgz` and `wrist-low-res.tgz`, Josh Mandel's own studies shared publicly by choice in `jmandel/my-health-data`) are **read-only** on `/api/demo-shares` and never expose a `controlToken`.
   - Users can click **"Clone to Sandbox Share"** (`POST /api/shares/{id}/clone`) or upload their own files to get an isolated, time-limited sandbox share with its own `controlToken` to test taking links offline, adding passcodes, or appending studies.
   - `POST /api/shares` and file `PUT`s enforce size and count quotas (e.g., max 150 MB per share, max 32 files per share, max 50 active sandbox shares, automatic expiry cleanup) so the server cannot be abused as an open file host.
3. **Persistent On-Disk Layout (`--data-dir`, default `./data`, gitignored):**
   ```
   data/
   ├── samples/
   │   ├── mri-brain-2020.tgz
   │   └── wrist-low-res.tgz
   └── shares/
       └── {shareId}/
           ├── meta.json                 # ShareMetadata (mode, salted passcode_hash, remaining_attempts, online, exp, controlToken_hash, files)
           ├── bundle.jwe                # Compact JWE (alg:dir, enc:A256GCM, zip:DEF)
           └── {fileId}.bin              # 64 KiB STREAM-encrypted series files
   ```

### 2.2 Strict Crate Boundary Rules (Why WASM Compiles Cleanly)

| Crate | Target(s) | Allowed Dependencies | Forbidden Dependencies |
|---|---|---|---|
| **`shl-dicom-core`** | `native` AND `wasm32-unknown-unknown` | Pure-Rust crates only: `aes-gcm`, `hkdf`, `sha2`, `flate2` (`rust_backend`), `tar`, `zip` (pure Rust), `dicom-object`, `base64`, `serde`, `serde_json`, `getrandom` (`js` feature on wasm32). Operates strictly on `&[u8]` and `Read`/`Write` cursors. | **No** `std::fs`, **no** `tokio`, **no** `reqwest`, **no** C `-sys` crates (`zstd-sys`, `openjp2-sys`, etc.), **no** `wasm-bindgen`. |
| **`shl-dicom-wasm`** | `wasm32-unknown-unknown` | `shl-dicom-core`, `wasm-bindgen`, `js-sys`, `serde-wasm-bindgen`. | **No** `tokio`, **no** `std::fs`. Network I/O (`fetch` with `Range`) stays in TypeScript and passes `Uint8Array` chunks into WASM. |
| **`shl-dicom-server`** | `native` (`x86_64` / `aarch64`) | `shl-dicom-core`, `tokio`, `axum`, `tower-http`, `reqwest`, `clap`. Handles all disk I/O (`data/shares/...`) and HTTP serving. | Never linked into WASM. |

### 2.3 File-by-File Responsibilities

#### In `crates/shl-dicom-core/src/`:
- **`crypto.rs`**: Owns the cryptographic primitives in §9.2 (`derive_series_key`, `record_nonce`, `encrypt_series`, `decrypt_record`, `decrypt_range`). Zero knowledge of DICOM or FHIR.
- **`range.rs`**: Pure arithmetic mapping `[plaintext_start, plaintext_end)` to `(first_record, last_record)` and `[ciphertext_start, ciphertext_end)`.
- **`jwe.rs`**: Compact JWE encryption and decryption (`alg: "dir"`, `enc: "A256GCM"`, `zip: "DEF"`).
- **`shl.rs`**: Encodes/decodes `shlink:/` payloads and computes legal `flag` strings (`"U"`, `"LU"`, `"P"`, `"LP"`, `"L"`).
- **`bundle.rs`**: Builds the R4 `Bundle` JSON from ingested DICOM metadata and parses a decrypted `Bundle` back into a strongly-typed `StudyIndex` (computing cumulative byte offsets and covering 64 KiB record ranges for every instance).
- **`dicom_io.rs`**: Parses Part 10 files (or bare datasets), extracts study/series/instance metadata, and decodes **uncompressed and RLE** pixel data (pure Rust, zero C dependencies) with DICOM Window Center / Window Width into 8-bit RGBA buffers. Compressed transfer syntaxes (JPEG, JPEG-LS, JPEG 2000, HTJ2K) are handed as raw Part 10 `.dcm` bytes to Cornerstone's WASM codecs in the browser.
- **`packer.rs`**: Orchestrates grouping ingested DICOM files by `(StudyInstanceUID, SeriesInstanceUID)`, sorting by `(InstanceNumber, SOPInstanceUID)`, drawing random 16-byte `fileId`s, concatenating instances, calling `crypto::encrypt_series`, and building `bundle.jwe`. Also supports **appending** new studies/series to an existing decrypted `Bundle` (`L` flag).
- **`export.rs`**: Extracts individual Part 10 `.dcm` instance byte slices from decrypted series records using `instance.length`.

#### In `crates/shl-dicom-wasm/src/`:
- **`session.rs` (`WasmShlSession`)**: Holds the decrypted `StudyIndex`, the 32-byte `shl_key`, and a **bounded LRU sparse record cache** (capped at e.g. 64 MiB of verified 65,520 B records so multi-GB studies never exhaust `wasm32` memory). When JS fetches any HTTP `Range`, JS feeds the ciphertext into `ingest_ciphertext_range`, which verifies each 64 KiB record's GCM tag and populates the bounded cache.
- **`packer.rs` (`WasmPacker`)**: Allows the browser to pack `.tgz`, `.zip`, or `.dcm` files completely client-side and return `{ shlKey, bundleJwe, seriesFiles }` for zero-knowledge upload to `/api/shares`.

#### In `crates/shl-dicom-server/src/`:
- **`state.rs`**: Manages `./data/shares/{shareId}/meta.json`, in-memory 1-hour `/cap/{token}/` leases, and per-share `tokio::sync::broadcast` channels for live SSE telemetry.
- **`routes_api.rs`**: Implements the Zero-Knowledge Share & Control API (`POST /api/shares`, `PATCH /api/shares/{id}`, `PUT /api/shares/{id}/files/...`, `GET /api/shares/{id}/events`, `GET /api/demo-shares`).
- **`routes_shl.rs`**: Implements the receiver-facing SHL routes (`GET /shl/{id}/bundle.jwe`, `POST /shl/{id}`, `GET /shl/{id}/{fileId}.bin`, `GET /cap/{token}/...`) and the HTTP `206 Partial Content` byte-range responder (using `tokio::fs::File` + `AsyncSeekExt` so the server only reads the requested 64 KiB records from disk!).

## 3. `shl-dicom-core` Rust API Signatures (Detailed)

### 3.1 `crypto` & `range` Modules
```rust
pub const RECORD_PLAINTEXT: u64 = 65_520;
pub const TAG_LEN: u64 = 16;
pub const RECORD_CIPHERTEXT: u64 = 65_536;

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub struct CiphertextRange {
    pub first_record: u64,      // floor(start / 65520)
    pub last_record: u64,       // floor((end - 1) / 65520)
    pub ciphertext_start: u64,  // first_record * 65536 (inclusive)
    pub ciphertext_end: u64,    // min(C, (last_record + 1) * 65536) (exclusive)
    pub skip_prefix: usize,     // start - first_record * 65520
    pub length: usize,          // end - start
}

pub fn derive_series_key(shl_key: &[u8; 32], salt: &[u8; 16]) -> ([u8; 32], [u8; 12]);
pub fn ciphertext_length(plaintext_len: u64) -> u64;
pub fn ciphertext_range(start: u64, end: u64, plaintext_len: u64) -> Result<CiphertextRange>;
pub fn encrypt_series(plaintext: &[u8], shl_key: &[u8; 32], salt: &[u8; 16]) -> Vec<u8>;
pub fn decrypt_record(record_ct: &[u8], record_index: u64, key: &[u8; 32], base_nonce: &[u8; 12]) -> Result<Vec<u8>>;
pub fn decrypt_range(ciphertext_slice: &[u8], start: u64, end: u64, plaintext_len: u64, shl_key: &[u8; 32], salt: &[u8; 16]) -> Result<Vec<u8>>;
```

### 3.3 `dicom_io`, `bundle` & `export` Modules
- **Inputs accepted by `IngestSession`:**
  - `ingest_dicom_bytes(raw_bytes: Vec<u8>)` (Part 10 file or bare dataset; skips `DICOMDIR`)
  - `ingest_tar_gz(tgz_bytes: &[u8])`
  - `ingest_zip(zip_bytes: &[u8])`
- **Outputs from `IngestSession::pack(shl_key: &[u8; 32])`:**
  - `PackedStudySet`:
    - `bundle_json: String` (FHIR R4 `Bundle` with `Patient` + one `ImagingStudy` per study)
    - `bundle_jwe: String`
    - `series_files: Vec<PackedSeriesFile>` (`{ file_id: String, salt: [u8; 16], plaintext_len: u64, ciphertext: Vec<u8> }`)
- **Parsed Index (`StudyIndex` extracted from decrypted FHIR Bundle):**
  - Lists every `StudySummary -> SeriesSummary -> InstanceSummary`:
    ```rust
    pub struct InstanceSummary {
        pub uid: String,
        pub sop_class: String,
        pub number: Option<i32>,
        pub offset: u64,        // computed sum of prior instance lengths in series
        pub length: u64,        // from https://example.org/shl-dicom/length
        pub first_record: u64,  // floor(offset / 65520)
        pub last_record: u64,   // floor((offset + length - 1) / 65520)
    }
    ```
- **Pixel Decoding (`decode_dicom_slice`):**
  - Input: `dicom_part10_bytes: &[u8]`, `override_wc: Option<f64>`, `override_ww: Option<f64>`
  - Output:
    ```rust
    pub struct DecodedSlice {
        pub width: u32,
        pub height: u32,
        pub rgba: Vec<u8>,      // width * height * 4 bytes ready for Canvas ImageData
        pub window_center: f64,
        pub window_width: f64,
        pub min_pixel: f64,
        pub max_pixel: f64,
        pub instance_number: Option<i32>,
        pub sop_instance_uid: String,
    }
    ```
- **Streaming Original DICOM Export (`exporter.ts` + `export.rs`):**
  - Rather than buffering an entire series or study `.zip` inside `wasm32` linear memory, JS streams each series' `{fileId}.bin` (or iterates instance-by-instance), verifies records via WASM, and pipes each reconstructed Part 10 `.dcm` file directly into a streaming JS ZIP writer (with ZIP64 support) or a directory via the browser File System Access API.

## 4. `shl-dicom-wasm` Browser API (`wasm-bindgen`)

### 4.1 `WasmShlSession` (Viewing, Range Planning, Decrypting, Exporting)
- `WasmShlSession::from_shlink_and_jwe(shlink_uri: &str, bundle_jwe: &str) -> Result<WasmShlSession, JsError>`
- `session.index_json() -> String`: Returns JSON of `StudyIndex` (patient name/DOB, studies, series, instance offsets, record counts, total byte sizes).
- `session.plan_instance_range(study_idx: usize, series_idx: usize, instance_idx: usize) -> JsValue`:
  - Returns `{ fileId, firstRecord, lastRecord, ciphertextStart, ciphertextEnd, rangeHeader: "bytes=a-b" }`.
- `session.ingest_ciphertext_range(file_id: &str, first_record: u32, ciphertext: &[u8]) -> Result<JsValue, JsError>`:
  - Verifies the GCM tag of each 64 KiB record in `ciphertext`, stores verified plaintext records in the session's sparse record cache for `file_id`, and returns `{ verifiedRecords: [u32, ...], totalVerifiedBytes: u64 }`.
- `session.has_instance(study_idx: usize, series_idx: usize, instance_idx: usize) -> bool`:
  - True if all records `first_record..=last_record` for that instance are in the verified cache.
- `session.get_instance_dicom(study_idx: usize, series_idx: usize, instance_idx: usize) -> Result<Uint8Array, JsError>`:
  - Returns the exact original Part 10 `.dcm` bytes for that instance from the verified record cache.
- `session.render_instance_rgba(study_idx: usize, series_idx: usize, instance_idx: usize, wc: Option<f64>, ww: Option<f64>) -> Result<JsValue, JsError>`:
  - Decodes uncompressed/RLE cached instances and returns `{ width, height, rgba: Uint8Array, windowCenter, windowWidth, minPixel, maxPixel }` (or signals the frontend to pass `get_instance_dicom()` to Cornerstone's codec for compressed transfer syntaxes).

### 4.2 `WasmPacker` (Browser-Side Zero-Knowledge Packing)
- `WasmPacker::new() -> WasmPacker` (or `WasmPacker::from_existing_bundle(shl_key_b64: &str, bundle_jwe: &str)` for `L`-flag study addition!)
- `packer.add_tgz(bytes: &[u8])` / `packer.add_zip(bytes: &[u8])` / `packer.add_dicom_file(bytes: &[u8])`
- `packer.finalize() -> Result<JsValue, JsError>`:
  - Generates a 32-byte SHL `key` (or uses the existing key), packs each new series into `{ fileId, ciphertext: Uint8Array }`, encrypts `bundle.jwe`, and returns `{ shlKey: string, bundleJwe: string, bundleJson: string, seriesFiles: [{ fileId, ciphertext }] }`.

## 5. `shl-dicom-server` HTTP REST & SHL Protocol Specification

### 5.1 Zero-Knowledge Share & Control Endpoints

| Method & Path | Auth | Request Body / Params | Response (`200 OK` / `201 Created`) |
|---|---|---|---|
| `POST /api/shares` | None (quota-limited) | `{ mode?: "U"\|"manifest", passcode?: string, exp?: number, longLived?: boolean, label?: string }` | `ShareStatusResponse` (includes `controlToken`, `shareId`, `shlUrl`, `shlFlag`) |
| `POST /api/shares/{id}/clone` | None (quota-limited) | `{}` (clones a read-only demo share into an isolated sandbox share) | `ShareStatusResponse` (with fresh `shareId` & `controlToken`) |
| `GET /api/shares/{id}` | `Bearer {controlToken}` | — | `ShareStatusResponse` |
| `PATCH /api/shares/{id}` | `Bearer {controlToken}` | `{ mode?: "U"\|"manifest", passcode?: string\|null, online?: boolean, exp?: number\|null, longLived?: boolean, label?: string, revokeCapabilities?: boolean }` | Updated `ShareStatusResponse` |
| `PUT /api/shares/{id}/files/bundle.jwe` | `Bearer {controlToken}` | Raw compact JWE (`application/jose`) | `{ ok: true, size: number }` |
| `PUT /api/shares/{id}/files/{fileId}.bin` | `Bearer {controlToken}` | Raw encrypted series bytes (`application/octet-stream`) | `{ ok: true, fileId: string, size: number }` |
| `DELETE /api/shares/{id}/files/{fileId}.bin` | `Bearer {controlToken}` | — | `{ ok: true }` |
| `GET /api/shares/{id}/events` | `Bearer {controlToken}` (fetched via `fetch` stream, never in URL query) | SSE stream | `event: access\ndata: {"ts":...,"method":"GET","path":"...","range":"bytes=65536-131071","status":206,"bytes":65536,"recipient":"..."}\n\n` |
| `GET /api/demo-shares` | None | — | `{ shares: [{ id, title, description, shlinkUri, readOnly: true, status }] }` (never exposes `controlToken`) |

**Passcode & Security Rules enforced by the Server:**
- Only a salted hash (`sha256(salt || passcode)`) is stored in `meta.json`, never the plaintext passcode.
- Each share has a lifetime `remainingPasscodeAttempts` counter (default `5`), decremented atomically under a mutex before validating a passcode attempt. Once `remainingPasscodeAttempts` reaches `0`, the share is permanently disabled (`404` on all SHL routes), including under concurrent requests.
- Setting a non-empty `passcode` via `PATCH` automatically sets `mode = "manifest"`, resets `remainingPasscodeAttempts = 5`, and invalidates the old U-mode URL (`404`).
- Clearing `passcode` (`"passcode": null`) allows `mode = "U"` or `mode = "manifest"`.
- `shlFlag` is computed automatically in alphabetical order:
  - `mode == "U"`: `"LU"` if `longLived` else `"U"`
  - `mode == "manifest"`: `"LP"` if `longLived && hasPasscode`, `"L"` if `longLived`, `"P"` if `hasPasscode`, or `null` if neither.
- `shlUrl` is `{origin}/shl/{id}/bundle.jwe` when `mode == "U"`, and `{origin}/shl/{id}` when `mode == "manifest"`.

### 5.2 SHL Resolution & Range Endpoints

| Method & Path | Condition | Behaviour |
|---|---|---|
| `GET /shl/{id}/bundle.jwe?recipient=...` | `online && !expired && mode == "U" && !hasPasscode` | Returns `bundle.jwe` (`200 OK`, `application/jose`). Returns `404` if offline/expired/manifest-mode. |
| `GET /shl/{id}/{fileId}.bin` | `online && !expired && mode == "U" && !hasPasscode` | Honours `Range: bytes=a-b` (`206 Partial Content` + `Content-Range: bytes a-b/C`, `Content-Type: application/octet-stream`, no `Content-Encoding`, `Access-Control-Allow-Origin: *`) or `200 OK`. |
| `POST /shl/{id}` | `online && !expired && mode == "manifest" && remainingAttempts > 0` | Atomically checks/decrements `remainingPasscodeAttempts` on mismatch (returns `401` with `remainingAttempts`, or `404` once exhausted). On match, mints 1-hour `capToken` (32 random bytes, base64url) and returns `{ "files": [{ "contentType": "application/fhir+json;fhirVersion=4.0.1", "location": "{origin}/cap/{capToken}/bundle.jwe" }] }`. |
| `GET /cap/{capToken}/bundle.jwe` | `online && !expired && capToken.valid()` | Returns `bundle.jwe` (`200 OK`). Returns `404`/`403` if share is taken offline or `capToken` expired (>1 hr or revoked via `revokeCapabilities`). |
| `GET /cap/{capToken}/{fileId}.bin` | `online && !expired && capToken.valid()` | Honours `Range: bytes=a-b` (`206 Partial Content`, no `Content-Encoding`) or `200 OK`. |

## 6. Comprehensive Test Plan Across Stages

### Stage 1 Tests (`cargo test -p shl-dicom-core`)
1. **`test_appendix_b_vector`**: Asserts `derive_series_key`, `encrypt_series`, record tags, ciphertext SHA-256, and instance-2 `decrypt_range(70000, 150000)` match Appendix B and `reference/test-vector.ts` byte-for-byte.
2. **`test_range_and_record_edge_cases`**:
   - Plaintext length that is an exact multiple of `65,520` bytes (e.g., `65,520` and `131,040`).
   - An instance spanning 4+ records (`250,000` bytes).
   - A range starting on an exact record boundary (`start = 65,520`).
   - A range ending in the short final record (`end = P`).
   - A 0-length or inverted range (`start == end` or `start > end`) returning `Err`.
3. **`test_tamper_and_truncation`**: Flipped ciphertext bit, swapped record 0 and 1, truncated final record, wrong `fileId` salt all return `Err`.
4. **`test_jwe_roundtrip_and_fresh_iv`**: Encrypts a FHIR Bundle as `dir` + `A256GCM` + `DEF`, verifies compact format has 5 dot-separated parts with empty encrypted key, verifies two encryptions produce distinct 12-byte IVs, and decrypts back to identical JSON.
5. **`test_pack_and_lossless_roundtrip_mri_and_wrist`**:
   - Ingests `data/samples/mri-brain-2020.tgz` and `data/samples/wrist-low-res.tgz` into one multi-study Bundle.
   - Verifies `Bundle` has 2 `ImagingStudy` resources and valid `file` / `length` extensions.

### Stage 2 Tests (`cargo test -p shl-dicom-server`)
1. **`test_zero_knowledge_upload_and_u_mode_range`**:

2. **`test_passcode_attempt_limit_and_concurrency`**:

   - Fires 10 concurrent `POST /shl/{id}` requests with a wrong passcode; verifies atomic counting allows at most 5 failures (`401`) and subsequent requests (even with the *correct* passcode) return `404`.
